③ Discovery Walk failure classes → emergent clusters → criteria

How each failure was diagnosed

Every failed session was read for its first thing wrong, and each finding was classified behavioral (an eval belongs here) or infrastructure (a fix belongs elsewhere). Failures were then grouped into categories that emerged from the reading itself — never from a pre-made list, which would bias what we find. Each category ended one of three ways: it became an eval criterion, it was routed to diagnostics as an infrastructure fix, or it was dropped as a one-off.

How to read a criterion card

Each card is one recommended check. THE CHECK is what gets verified — true or false per session, never a score. WHY IT EXISTS shows the real past failures that created it: the colored strip is every analyzed session (red = this check failed there), and the purple session chips are clickable — peek at the actual trace. EVIDENCE SEEN quotes the exact strings the verdicts cited. GATES RELEASE? says whether a failure of this check blocks a release.

Proposed regression cases — keep these mistakes fixed forever

Some sessions showed failure shapes worth keeping as test cases: each becomes a synthetic input that recreates the situation, so every future evaluation automatically re-checks that this exact mistake hasn't come back. Each row tells you the real story it came from, how that session was judged, and what the test case will prevent.
